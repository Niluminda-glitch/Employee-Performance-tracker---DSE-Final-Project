================================================================================
                    MANAGER DASHBOARD - TECHNICAL FEATURE OVERVIEW
================================================================================

This document provides detailed technical analysis of Manager Dashboard features,
focusing on system interactions, database relationships, and architectural patterns
for creating comprehensive class diagrams and sequence diagrams.

================================================================================
1. USER MANAGEMENT SYSTEM
================================================================================

FEATURE OVERVIEW:
Complete CRUD operations for user lifecycle management with role-based access control,
QR code generation, and real-time validation.

UNIQUE DIFFERENTIATORS:
- QR Code credential sharing for new users
- Real-time role-based dashboard redirection
- Integrated Google OAuth with Supabase verification
- Self-protection mechanisms (managers can't deactivate themselves)
- Hierarchical supervisor-employee relationship management

SYSTEM INTERACTIONS:

User → Manager Dashboard → AuthMiddleware → Database
Manager → UserController → Supabase → EmailService → QRGenerator

DATABASE RELATIONSHIPS:
- users table (primary entity)
- departments table (foreign key relationship)
- user_skills junction table (many-to-many)
- supervisor relationships (self-referencing foreign key)

KEY CLASSES FOR CLASS DIAGRAM:
- ManagerDashboard (React Component)
- UserController (Backend Controller)
- User (Database Model)
- Department (Database Model)
- AuthMiddleware (Security Layer)
- QRCodeGenerator (Utility Service)
- EmailVerificationService

SEQUENCE DIAGRAM FLOW:
1. Manager clicks "Add User"
2. Form validation (client-side)
3. API call to /manager/users (POST)
4. AuthMiddleware validates manager role
5. UserController processes request
6. Database transaction (create user + assign relationships)
7. QR code generation with credentials
8. Email notification (optional)
9. Real-time UI update
10. Success notification

CRITICAL INTERACTIONS:
- Role validation at multiple layers
- Transactional user creation with relationship assignments
- Real-time state synchronization
- Error handling and rollback mechanisms

DETAILED DATABASE SCHEMA RELATIONSHIPS
================================================================================

PRIMARY ENTITIES:
- users (id, email, full_name, role, status, department_id, supervisor_id)
- departments (id, name, description, headcount, created_at)
- tasks (id, user_id, title, status, due_date, completion_date)
- notifications (id, user_id, title, message, type, is_read)
- requests (id, user_id, type, status, start_date, end_date)

JUNCTION TABLES:
- user_skills (user_id, skill_id, proficiency_level)
- user_departments (user_id, department_id, role_in_department)
- notification_recipients (notification_id, user_id, delivery_status)

AUDIT TABLES:
- user_audit_log (action, user_id, changed_by, timestamp, changes)
- department_audit_log (action, department_id, changed_by, timestamp)
- approval_history (request_id, approver_id, action, timestamp, comments)

CACHE TABLES:
- trends_cache (api_endpoint, response_data, cache_expiry)
- analytics_cache (user_id, metric_type, calculated_value, cache_time)
