# Database Schema Diagram (ERD) - Drawing Instructions
## Employee Tracking System - Professional ERD Creation Guide

### 📋 OVERVIEW
This document provides detailed instructions for creating a professional Entity Relationship Diagram (ERD) for the Employee Tracking System database schema.

### 🎯 DIAGRAM REQUIREMENTS
- **Tool Recommendations**: Draw.io, Lucidchart, MySQL Workbench, or any professional ERD tool
- **Format**: Landscape orientation (A3 or A4)
- **Style**: Professional, clean, and readable
- **Colors**: Use consistent color scheme (suggested: blue for tables, green for relationships)

### 🔗 RELATIONSHIP SPECIFICATIONS

#### Primary Relationships (draw with solid lines):

1. **DEPARTMENTS → USERS** (One-to-Many)
   - From: DEPARTMENTS.id
   - To: USERS.department_id
   - Cardinality: 1:N
   - Label: "has_employees"

2. **USERS → USERS** (Self-Referential)
   - From: USERS.id
   - To: USERS.supervisor_id
   - Cardinality: 1:N
   - Label: "supervises"

3. **USERS → TASKS** (One-to-Many - Assignee)
   - From: USERS.id
   - To: TASKS.assignee_id
   - Cardinality: 1:N
   - Label: "assigned_to"

4. **USERS → TASKS** (One-to-Many - Supervisor)
   - From: USERS.id
   - To: TASKS.supervisor_id
   - Cardinality: 1:N
   - Label: "supervises_tasks"

5. **USERS → USER_SKILLS** (One-to-Many)
   - From: USERS.id
   - To: USER_SKILLS.user_id
   - Cardinality: 1:N

6. **SKILLS → USER_SKILLS** (One-to-Many)
   - From: SKILLS.id
   - To: USER_SKILLS.skill_id
   - Cardinality: 1:N

7. **USERS → NOTIFICATIONS** (One-to-Many - Receiver)
   - From: USERS.id
   - To: NOTIFICATIONS.user_id
   - Cardinality: 1:N
   - Label: "receives"

8. **USERS → NOTIFICATIONS** (One-to-Many - Related User)
   - From: USERS.id
   - To: NOTIFICATIONS.related_user_id
   - Cardinality: 1:N
   - Label: "mentioned_in"

9. **TASKS → NOTIFICATIONS** (One-to-Many)
   - From: TASKS.id
   - To: NOTIFICATIONS.related_task_id
   - Cardinality: 1:N
   - Label: "generates"

10. **USERS → REQUESTS** (One-to-Many - Submitter)
    - From: USERS.id
    - To: REQUESTS.user_id
    - Cardinality: 1:N
    - Label: "submits"

11. **USERS → REQUESTS** (One-to-Many - Approver)
    - From: USERS.id
    - To: REQUESTS.approver_id
    - Cardinality: 1:N
    - Label: "approves"

### 🎨 VISUAL FORMATTING GUIDELINES

#### Color Scheme:
- **Table Headers**: Dark Blue (#2E4A6B)
- **Primary Keys**: Gold/Yellow (#FFD700)
- **Foreign Keys**: Orange (#FF8C00)
- **Regular Fields**: Light Gray (#F5F5F5)
- **Relationship Lines**: Dark Green (#228B22)
- **Junction Table**: Light Purple (#DDA0DD)

#### Typography:
- **Table Names**: Bold, 14pt, ALL CAPS
- **Field Names**: Regular, 10pt
- **Data Types**: Italic, 9pt
- **Constraints**: Bold, 8pt (PK, FK, UK)

#### Line Styles:
- **Solid Lines**: Primary relationships
- **Dashed Lines**: Optional relationships
- **Thick Lines**: Strong relationships (1:N)
- **Thin Lines**: Weak relationships

#### Symbols:
- **🔑**: Primary Key
- **🔗**: Foreign Key
- **⭐**: Unique Key
- **📊**: Enum Field
- **⏰**: Timestamp Field
